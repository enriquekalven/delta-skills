# Structure Decision Tree: Choosing Organization Design

This decision tree helps determine whether to organize by Function, Customer, Geography, or Hybrid.

## DECISION TREE: Should we organize by Function, Customer, Geography, or Hybrid?

```
START: What are the primary Coherent Actions?
   ├─ If: Actions are customer/segment-specific
   │   └─ PREFER: Customer/Segment structure
   │       (Each segment has own P&L, GTM, ops; central provides shared capability)
   │
   ├─ If: Actions are deep-expertise functions (engineering, data, compliance)
   │   └─ PREFER: Functional structure
   │       (VP Eng owns engineering excellence; VP Product owns product strategy)
   │
   ├─ If: Actions span geography with local customization
   │   └─ PREFER: Geographic structure
   │       (Each region has P&L; HQ provides strategy + capability)
   │
   └─ If: Actions require multiple of above
       └─ USE: Matrix structure (avoid if possible; see governance section)
```

## Tradeoffs by Structure Type

### FUNCTIONAL STRUCTURE
**When to use:** Deep expertise is competitive advantage; functions operate independently
- Pros: Specialization, deep skill building, efficient resource use
- Cons: Silos between functions, slow customer decisions, cross-functional friction
- Risk: Loses customer focus; may optimize for function vs. customer value

### CUSTOMER/SEGMENT STRUCTURE
**When to use:** Customer needs vary; accountability must flow to one person per segment
- Pros: Fast customer decisions, clear accountability, customer focus embedded
- Cons: Duplicated functions, harder to scale shared expertise
- Risk: Segments diverge in processes; scaling becomes chaotic

### GEOGRAPHIC STRUCTURE
**When to use:** Markets vary by region; local adaptation matters; regions are P&Ls
- Pros: Local market responsiveness, regional P&L accountability
- Cons: Headquarters doesn't feel close to market; strategic consistency harder
- Risk: Regions optimize locally; miss global opportunities

### MATRIX STRUCTURE
**When to use:** Only if absolutely necessary (multiple strategic dimensions matter equally)
- Pros: Balances multiple priorities
- Cons: Ambiguous accountability, slower decisions, political maneuvering
- Risk: Becomes bureaucratic; "matrix" becomes excuse for unclear decisions
- **Mitigation if required:** Crystal-clear RACI matrix; explicit decision rights; strong governance

## Decision Framework

Ask these questions in sequence:

1. **What's the primary value driver?** (Customer, expertise, geography, speed?)
2. **Where does accountability need to flow?** (To customer relationship owner, function head, regional leader?)
3. **What decisions happen most frequently?** (Product decisions, customer decisions, operational decisions?)
4. **How fast do those decisions need to be made?** (Days? Hours? Weeks?)
5. **Can shared services provide some functions, or must they be embedded in each unit?**

Based on answers, the structure becomes clear. If multiple answers conflict, you likely need hybrid structure—and you need exceptional governance to manage the complexity.
